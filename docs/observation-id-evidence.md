# Observation-ID evidence — 2026-10-12

The v7 traffic investigation obtained a supported search/traffic assessment but
lost its final correct cause to invalid copied metric excerpts. This change lets
the model select observation IDs while the server attaches real excerpts. The
historical live result remains a diagnostic miss. No new provider calls were made.

## Model input and server output

The model-facing final schema still has six fields, with up to three unique
observation IDs in `evidence`. A supported traffic submission can be:

```json
{"status":"diagnosed","root_cause_service":"search","fault_type":"traffic_spike","evidence":["obs-12","obs-13"],"action":null,"target":null}
```

The server resolves each selected ID from successful observations in the current
investigation. The API/result/trace still returns evidence objects containing
`observation_id` and `quote`, so saved replays retain readable exact source excerpts.
The submitted model object is not mutated. Remediation prose remains generated by
the server. Model-authored quotes and remediation are absent from the new schema.

For structured MCP assessments, the server extracts the actual status field from
the original JSON spelling/spacing. For metrics, it selects the actual summary
header; for service snapshots, the diagnosed service row when present; for log
search, a recent actual log line or the coverage warning. Other outputs use the
first nonempty line. Excerpts are bounded to 240 characters, without reformatting
or paraphrasing. A selected ID links to the full observation in the investigation
trace. An excerpt is a deterministic source selection, not a model-authored causal
explanation or a complete representation of every observation.

Unknown IDs, duplicate IDs, mixed reference formats, empty/unusable observations
and failed tool results are rejected. A cached observation retains its original
ID and can still be selected. The server only sees successful observations from
this run, rather than arbitrary identifiers from saved experiments.

## Diagnostic and recovery requirements remain

Every fault still requires a selected, authentic assessment from its named MCP
tool, for the exact diagnosed service/fault. Selecting a runbook or an unrelated
metric observation cannot substitute for the required check. Wrong-service,
wrong-fault, missing, unknown or conflicting assessments still reject the
diagnosis, even when action/target are null. A supported assessment must be
explicitly selected; the server does not silently add one to justify a guess.

Replica headroom remains a separate recovery check. A supported traffic diagnosis
can be accepted while its scale proposal is removed as blocked/unverified. No
recovery action is executed. The 1,000-output-token, 24,000-input-token and 12-call
limits and existing spending reservations remain unchanged.

Older clients may still submit the former quoted-reference objects. That
compatibility path continues validating their exact substring claims and size
limits. It does not silently repair invented quotes. Mixing the old and new
reference formats is rejected. The subsequent two-case live validation is recorded in
[live-v8-validation.md](live-v8-validation.md), followed by
[five fresh-seed cases](live-v8-fresh-faults.md). The latter observed a log excerpt
relevance limitation; larger-suite behavior remains unmeasured.

## Offline recorded-selection replay

`evals/fixtures/v7-traffic-reference-schedule.json` contains only the original
v7 tool-use schedule and submitted arguments. It excludes model text, conversation
prompts, credentials and headers. The replay converts each quoted evidence object
to its existing observation ID. It preserves every service/fault/action hypothesis,
source choice, tool argument and ordering. No model generates new responses.

With real in-memory MCP and the new interface, the migrated schedule measured:

- **8 scripted responses**, **16 MCP executions**, **2 validation rejections**.
- Both inventory/bad_deploy rollback proposals remain rejected because their
  required change assessment is unknown.
- The final search/traffic_spike diagnosis is accepted; scaling is removed with
  recovery_status=blocked and no action/target.
- **3/3** attached excerpts are exact substrings of the selected observations.
- Zero output truncations and **zero provider calls**.

The original live run consumed eight calls and 16 MCP executions but had three
rejections and a forced abstention. This replay isolates reference formatting;
it does not estimate new Haiku accuracy, cost, latency or its likelihood of making
those selections under a changed prompt. Its result is in `results/references.json`
with source/fixture hashes and validation messages. No historical live grade was
changed.

- The six-fault matrix still accepted **78/78** expected supports and rejected

  other historical live results are preserved.
- Tailored rule outcomes remain **60/60** original and **8/24** on each challenge
